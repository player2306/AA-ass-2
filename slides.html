Question 1b

DP finds the minimum-energy seam

Optimal · O(mn)
M(i,j) = e(i,j) + min M(i−1, j−1) M(i−1, j) M(i−1, j+1)

Base case M(1,j) = e(1,j). The optimal seam ends at argminj M(m,j), then follows the stored choices back to the top.

Question 2a(i)

How many seams are there?

At least exponential
S(m, n) ≥ 2m

S(m, n) = number of vertical seams in an m × n image, n > 1

1

A seam picks one pixel per row

From column j, the next row's pixel must be in column j−1, j, or j+1.

2

Count only columns 1 and 2

Because n > 1, both columns exist. They are adjacent, so any sequence of column-1 / column-2 choices is a valid seam.

3

2 choices in each of m rows

That gives exactly S(m, 2) = 2m seams. Wider images only add more, so S(m, n) ≥ 2m.

2m is exponential in m. This proves the claim and rules out brute force; DP (next slide) needs only O(mn).

Speaker notes (~40 s)
  • Question 2a(i) asks how many seams there are. A seam takes one pixel per row, and each next pixel must be in the same or an adjacent column.
  • Since n is greater than 1, there are at least two columns, so I only count seams that use columns 1 and 2. They're adjacent, so every row can pick either one freely.
  • That's 2 choices in each of m rows, so 2 to the m seams. For m = 3, these are the 8 on the right.
  • Wider images only add seams, so the count is at least 2 to the m: exponential, which is why brute force fails.
Question 2a(ii)

Relating a seam to subproblems

Dynamic programming

Subproblem

DP[i,j] = minimum total energy of a seam ending at pixel (i,j).

DP[i,j] = e[i,j] + min(DP[i−1,j−1], DP[i−1,j], DP[i−1,j+1])

Base: DP[1,j] = e[1,j] · out-of-range columns = ∞ · answer: minj DP[m,j], then backtrack.

Why DP works

Optimal substructure: if the path into the parent weren't the cheapest, swapping in a cheaper one would give a cheaper seam. Contradiction.
Overlapping subproblems: each DP[i−1,k] is reused by up to 3 cells below, so it is stored once.

Rows are filled top to bottom: O(mn) time and space, versus ≥ 2m seams for brute force.

Seam carving · Assignment 2Subproblems
Speaker notes (~40 s)
  • For 2a(ii) we use dynamic programming. DP[i,j] is the cheapest seam ending at pixel (i,j). The first row is just its own energy.
  • Every other cell adds its energy to the cheapest of the three cells above it. Neighbours outside the image count as infinity.
  • This works because of optimal substructure, and each value is reused by up to three cells, so we compute it once.
  • In this example the last row's minimum is 5, and backtracking gives the seam 2, 1, 2. That's O(mn) instead of exponential.
Question 2b

Divide & conquer for Sobel convolution?

No asymptotic gain

Sobel: fixed 3×3 work per pixel

Gx-101-202-101 Gy-1-2-1000121 G = √(Gx² + Gy²)

Constant work per pixel → O(mn). Every output pixel must be written, so no method beats Ω(mn).

Divide & conquer into 4 regions, N = mn

Regions write into one shared output (O(1) combine):

T(N) = 4T(N/4) + O(1) ⇒ Θ(N)

Each region copies its own output back (O(N) per level):

T(N) = 4T(N/4) + O(N) ⇒ Θ(N log N)

Verdict

D&C does not reduce the complexity of a fixed-size Sobel filter: at best the same O(mn), at worst O(N log N). Its real benefit is parallelism: independent regions can run on separate CPU cores.

FFT convolution is also D&C, O(N log N), but only pays off for large kernels, not 3×3.
Seam carving · Assignment 2Divide & conquer
Speaker notes (~40 s)
  • 2b asks if divide and conquer speeds up the Sobel gradient. Sobel uses two fixed 3×3 kernels, so each pixel is constant work: O(mn). And every pixel must be computed, so nothing beats that.
  • Splitting into four regions that write into one shared array gives T(N) = 4T(N/4) + O(1), still O(N). If each region copies its output back, that's O(N) per level, so N log N, which is worse.
  • Border pixels also need a one-pixel overlap. So D&C doesn't improve the complexity; its real benefit is running regions in parallel on multiple cores.
Question 3

Greedy seam carving

Local decisions

Algorithm

  1. Start at the minimum-energy pixel in the first row.
  2. In each next row, move to the lowest-energy of the three adjacent pixels.
  3. Never look ahead and never backtrack.
  4. Remove the resulting connected seam, update the energy, repeat.
for i in range(1, m): j = argmin(energy[i, j-1 : j+2]) seam.append(j)

Question 4 · Graph cut

A seam is a cut through a pixel graph

Min-cut / max-flow
1

One node per pixel

Pixel (i,j) is a node. The source s links to every first-column pixel with ∞ capacity.

2

Cutting an edge removes a pixel

(i,j) → (i,j+1) has capacity e(i,j), the cost of removing (i,j). Forward energy |I(i,j+1) − I(i,j−1)| is also supported.

3

∞ edges force a valid seam

Backward (i,j+1) → (i,j): each row is cut exactly once. Diagonals (i,j) → (i±1,j−1): neighbouring rows are cut at most one column apart.

4

Last column → sink costs its energy

Our change to the spec: with ∞ here the last column could never be removed. Using e(i,W−1) lets the seam use every column, like DP.

5

Cheapest cut = cheapest seam

Every finite cut is a seam and costs that seam’s energy, so by max-flow min-cut the seam is optimal: the same objective as DP.

Graph size: V = mn + 2 nodes, E ≈ 4mn edges. Max-flow by Dinic O(V²E) (default) or Edmonds–Karp O(VE²), both implemented from scratch in graphcut.py, with no max-flow library. Horizontal seams: transpose the image.

Seam carving · Assignment 2Graph cut
Speaker notes
  • For Question 4, I did seam carving with graph cuts: instead of building the seam row by row like DP, I turn the whole image into a flow network and find its cheapest cut.
  • Each pixel is a node, with a source on the left and a sink on the right. The edge to a pixel’s right neighbour costs that pixel’s energy, so cutting it removes that pixel.
  • Infinite backward and diagonal edges make sure a cut crosses each row once and never jumps more than one column, so every cut is a valid seam.
  • One change from the spec: the last column links to the sink with its own energy instead of infinity, so it can be removed too, just like in DP.
Question 4 · Algorithm

Max-flow finds the cut, BFS reads the seam

Dinic’s algorithm
for each seam: e = energy(image) # Sobel or forward G = build_seam_graph(e) # mn+2 nodes while BFS(s) reaches t: # one Dinic round DFS pushes bottleneck f along each shortest path: residual −= f, reverse += f S = BFS(s) over spare capacity seam[i] = rightmost S pixel in row i image = remove(image, seam)
A

Level graph (BFS)

Label every node with its distance from s, using only edges that still have spare capacity.

B

Blocking flow (DFS)

Push flow along shortest paths. Reverse edges let later paths undo earlier ones.

C

Read the cut

Once t is unreachable, the nodes s still reaches form S. Every edge leaving S is full.

Numbers in nodes are energies. Coral: source side S and the cut edges · amber: round 2’s path through an ∞ diagonal · dashed violet: ∞ edges.

Testing · Correctness

Proving the seam is the cheapest

Brute force as the oracle

DP vs every possible seam

A 5×4 grid has only 178 connected seams, so the test tries them all. On 25 random grids DP’s seam must cost exactly the minimum.

for _ in range(25): e = rng.integers(0, 10, (5, 4)) s = _find_vertical_seam(e) assert cost(e, s) == \ best_seam_cost(e)

Graph cut is checked the same way in its author’s tests.

Fast path = slow path

After each seam, DP recomputes energy only beside the removed pixels. The test removes 10 seams and compares that map with a full Sobel recompute every time.

A second test puts cheap pixels at opposite borders: a seam may only join them by wrapping around the image, which DP must never do.

Speaker notes
  • The hard question is whether the optimal algorithms really are optimal. On tiny grids exhaustive search is cheap and gives the true answer.
  • DP’s speed-up only recomputes energy near the removed seam; if that were off by a column, seams would quietly get worse. Comparing with a full recompute catches it.
  • The contract tests run once per algorithm, so DP, greedy and graph cut must all behave the same at the edges, even though they pick different seams.
